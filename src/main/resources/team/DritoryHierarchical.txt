## 2. 패키지별 역할

### 2-1. exception (개인 수정 엄금)

- 프로젝트 전반에서 발생하는 예외를 관리하는 패키지
- 사용자 정의 예외 클래스 및 공통 예외 처리 클래스 배치
- 예외 처리 로직을 각 도메인에서 중복 작성하지 않도록 관리

### 2-2. food

식재료(Food) 도메인과 관련된 기능을 관리하는 패키지.

도메인별로 Controller, DTO, Repository, Service를 분리한다.

#### controller
- `FoodController`
  - 일반적인 페이지 요청 및 화면 이동 처리
- `FoodRestController`
  - REST API 요청 처리
  - JSON 형태의 데이터 요청 및 응답 담당

#### dto
클라이언트와 서버 사이에서 데이터를 전달하기 위한 객체 관리.

- `request` (필수)
  - 클라이언트로부터 전달받는 요청 데이터
  - 등록, 수정 등 기능별 요청 DTO 관리
- `response` (선택)
  - 클라이언트에게 반환할 데이터 객체 관리
  - Entity를 직접 반환하지 않고 필요한 데이터만 전달

#### repository
데이터베이스 접근을 담당하는 패키지.

- `JPAFoodRepository`
  - Spring Data JPA 기반 데이터 접근
  - Entity 중심의 기본 CRUD 및 데이터 관리
- `MFoodRepository`
  - MyBatis 기반 데이터 접근
  - 복잡한 SQL, JOIN, 집계 및 동적 쿼리 처리

#### service
- 비즈니스 로직 담당
- Controller와 Repository 사이에서 기능 수행
- 데이터 검증 및 처리 흐름 관리

---

### 2-3. entity

- JPA Entity 클래스 관리
- 데이터베이스 테이블과 매핑되는 객체 관리
- 공통으로 사용하는 Enum 클래스 관리

현재 관리 대상:
- `Food`
- `FoodProcessingType`

---

### 2-4. hierarchicalTemplate

- 프로젝트 계층 구조 및 패키지 구성 템플릿 관련 패키지
- 현재 프로젝트에서 사용하는 구조의 참고용 패키지

---

## 3. resources 패키지 역할

### mappers
- MyBatis XML Mapper 파일 관리
- SQL 쿼리 작성
- Repository 인터페이스와 Mapper XML 연결

### static
- 브라우저에서 직접 접근하는 정적 리소스 관리
- CSS, JavaScript, 이미지 파일 등

### templates
- Thymeleaf 기반 HTML 파일 관리
- Controller에서 반환하는 화면 템플릿 배치

### team
- 팀 프로젝트 관련 문서 보관
- 코드 컨벤션 및 패키지 구조 문서 관리
